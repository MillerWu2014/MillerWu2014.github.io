1. **出现`“org.apache.spark.SparkException: Task not serializable”`这个错误**

在编写`spark`程序是出现了`org.apache.spark.SparkException: Task not serializable`错误，由于在操作`RDD`算子`map`中使用到了类中定义的其他函数或者定义的其他变量，而引发的未序列化问题。在实际开发过程中难免会引用定义的其他函数或者变量进行操作。为了解决为序列化的问题需要对类进行序列化处理。下面的代码是未序列化之前：
```scala
case class TypeMatched(label: Boolean, features:Array[Int])

class loadData {
    /*
    * Created by Miller on 17-7-17.
    * Load sandbox's bson data from location and transform to rdd type
    * Use spark analysis data and static data
    * */
    
    val dataPath: String = "/opt/Project/spark_project/data/sbx_data/text_data_by_spark.csv"
    val sc: SparkContext = new SparkContext(new SparkConf().setMaster("local[*]").setAppName("LoadSandboxData"))
    
    // This method use to generate RDD
    def toRDD: RDD[Array[Int]] = {
        sc.textFile(dataPath).map(line => line.split(",").map(x => x.toInt))
    }
    
    private def IntToBoolean(s: Int): Boolean = if (s > 0) true else false
    
    def toTypeData(rdds: RDD[Array[Int]]) = {
        rdds.map(array => {
            val _label_ = IntToBoolean(array(0))
            val _features_ = array.slice(0, array.length)
            TypeMatched(_label_, _features_)
        })
    }
}
```
<!--more-->在运行是会出现错误：
`Exception in thread "main" org.apache.spark.SparkException: Task not serializable`
解决的方法：
(1).将类进行序列化,使用`extends Serializable`即可.
(2).若类中有不能序列化的变量或者函数需要进行特殊处理:`@transent`
修改后的代码如下:

```scala
class loadData extends Serializable {
    /*
    * Created by Miller on 17-7-17.
    * Load sandbox's bson data from location and transform to rdd type
    * Use spark analysis data and static data
    * */
    
    val dataPath: String = "/opt/Project/spark_project/data/sbx_data/text_data_by_spark.csv"
    
    @transient
    val sc: SparkContext = new SparkContext(new SparkConf().setMaster("local[*]").setAppName("LoadSandboxData"))
    
    // This method use to generate RDD
    def toRDD: RDD[Array[Int]] = {
        sc.textFile(dataPath).map(line => line.split(",").map(x => x.toInt))
    }
    
    private def IntToBoolean(s: Int): Boolean = if (s > 0) true else false
    
    def toTypeData(rdds: RDD[Array[Int]]) = {
        rdds.map(array => {
            val _label_ = IntToBoolean(array(0))
            val _features_ = array.slice(0, array.length)
            TypeMatched(_label_, _features_)
        })
    }
}
```
由于`spark`中`SparkContext`和`SparkConf`都是不能序列化的变量，因此需要对其标注为不需要进行序列化`(@transient)`.在处理之后代码能顺利运行了。得到结论：由于`Spark`程序中的`map`、`filter`等算子内部引用了类成员函数或变量导致该类所有成员都需要支持序列化，又由于该类某些成员变量不支持序列化，最终引发`Task`无法序列化问题。相反地，对类中那些不支持序列化问题的成员变量标注后，使得整个类能够正常序列化，最终消除`Task`未序列化问题。
另外还有一种处理的方式就是将要引用的函数或者变量定义到一个`object`类中，就像`java`中的`static`类。这样也可以不做序列化处理。下面可以修改成这样的代码进行测试：
```scala
object utilTool {
    def IntToBoolean(s: Int): Boolean = if (s > 0) true else false
}

class loadData {
    /*
    * Created by Miller on 17-7-17.
    * Load sandbox's bson data from location and transform to rdd type
    * Use spark analysis data and static data
    * */
    
    val dataPath: String = "/opt/Project/spark_project/data/sbx_data/text_data_by_spark.csv"
    val sc: SparkContext = new SparkContext(new SparkConf().setMaster("local[*]").setAppName("LoadSandboxData"))
    
    // This method use to generate RDD
    def toRDD: RDD[Array[Int]] = {
        sc.textFile(dataPath).map(line => line.split(",").map(x => x.toInt))
    }
    
    private def IntToBoolean(s: Int): Boolean = if (s > 0) true else false
    
    def toTypeData(rdds: RDD[Array[Int]]) = {
        rdds.map(array => {
            val _label_ = utilTool.IntToBoolean(array(0))  // utilTool.IntToBoolean
            val _features_ = array.slice(0, array.length)
            TypeMatched(_label_, _features_)
        })
    }
}
```
解决办法和编程建议：
(1)在`map`或者`filter`操作中不要引用类(一般是当前类)成员。如果函数可以独立出来，可以写在`object`类中，这样不需要进行序列化处理。
(2)如果不能避免上面1中的情况，就必须要做序列化处理：对类进行序列化，类中不能序列化的成员需要进行特殊标记处理，使得整个类能正常的序列化。

2. **`Spark`中对象的序列化**

在`RDD`的`API`里所引用的所有对象，都必须是可序列化的，因为RDD分布在多台机器是，代码和所引用的对象会序列化，然后复制到多台机器，所以凡是被引用的数据，都必须是可序列化的。例如，如下代码，就会报`java.lang.NotSerializableException: scala.util.Random` 异常：
```scala
val rnd = new Random()
rdd.mapPartition { x=>
  // ...
  val i = rnd.nextInt(10)
  // ...
}
```
因为`mapPartition`里引用了`rnd`, 而`Random`对象没有继承自`Serialize`，是不可序列化的，所以会报异常。把` val rnd = new Random()`移动到 `mapPartion()`里面才行。
在一个`RDD`的`api`里，不能引用另一个`RDD`。`RDD`是不可序列化的，在一个`RDD`的`api`里，不能引用另一个`RDD`。如果你在一个`RDD`的`API`里，例如`map()`里，引用了另一个`RDD`，编译虽然会通过，但是运行会出现` java.lang.NullPointerException`

3. **在IDEA中写scala时当两个类分别在两个文件中，引用时会出现错误：`Error:not found:type xxxxx`**

当在项目的代码`root`目录下创建两个类时，其中一个类去调用另外一个类时出现了错误：`error:not found type xxxxx`. 通过谷歌发现下很多人也遇到了同样的问题。很多处理的方式都最终放入同一个`scala`文件中。具体原因也不是清楚。通过多番测试解决方案如下:
![项目结构](/assets/img/posts/spark中遇到的问题汇总/tree.png)
(1)新建一个包，在包中将创建两个文件。其他代码和之前的代码一致，只需要在两个文件头中加上`package` 路径
原因分析：当将两个`scala`文件放入到根目录下(如上图中的`scala`目录下)就会出现上述的错误。当放入一个包内就不会出现这样的错误。而在`eclipse`中，在根目录创建文件时默认是放入到了一个`default package`的包下，因此也不会报错。因此可能是因为包和根目录的区别导致这个错误。
